# Sprint 0 y Sprint 1

## Sprint 0 — 03 al 04/11/2026 (timebox orientativo)
**Objetivo:** base mínima documentada y repositorios listos, no desarrollar todo el sistema.
**Entregables:** cuatro repos privados, workspace, instrucciones Copilot, backlog y specs MVP, modelo conceptual, plan de pruebas, bootstrap local aprobado.
**Salida:** poder iniciar HU-001 sin dudas críticas.

## Sprint 1 — 05 al 15/11/2026
**Objetivo:** flujo vertical admin configura → asigna → promotor inicia sesión → registra recepción → admin consulta.
**Secuencia:** seguridad; datos mínimos; asignación; recepción API; Flutter; consulta web; pruebas y demo.
**Criterio de éxito:** ejecutar el flujo con datos de demostración, registrar evidencia y no tener defectos bloqueantes.

## Capacidad y contingencia
Las 50 horas del desarrollo inicial son presupuesto de esfuerzo, no garantía de todas las HUs. Reservar tiempo de integración y demo; ante bloqueo, reducir catálogos y UI a lo indispensable, sin eliminar autorización ni transacciones.

## Scrum ligero
- Planning: 20–30 min al inicio del sprint.
- Daily personal: 5–10 min (hecho / siguiente / bloqueo).
- Review: demo con Samantha al final del sprint.
- Retro: 15 min, registrar una mejora.
- Backlog y estado en `sprint-backlog.md` (sin duplicar herramientas).
