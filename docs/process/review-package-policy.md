# Review package policy
At mandatory gates or escalation, use `scripts/New-ReviewPackage.ps1` via the review skill, or equivalent safe procedure if unavailable. The sibling `brand-promoter-reviews/` outside the workspace and all repos is the only review export location. Use a unique REVIEW identifier (e.g. REVIEW-0001-bootstrap). Produce report.md (Spanish), manifest.md, per-repo diffs, and optional sanitized test evidence/attachments. Zip only after review of the contents; return path. Never commit review exports.

## Baseline and coverage
Before a work item or approved batch, capture full commit SHA, branch, status and any pre-existing changes in each repo. Prefer clean worktrees; stop if unrelated changes would be mixed or baseline cannot be established. Record base SHAs in the external review/session evidence and reuse through local commits. For transition after Prompt 00, use observed current HEAD for a read-only snapshot; distinguish v0.4.0 policy changes from implementation. Never invent a historical baseline. If prior policy commits are to be reviewed, explicitly identify their predecessor SHAs. A clean snapshot may legitimately have empty diffs.

Capture net changes from base to current working tree, including committed, staged, unstaged, deleted and nonignored untracked files. Also inventory staged and unstaged changes separately so staged content overwritten in the worktree is not lost. Use a temporary Git index seeded from HEAD, stage the current snapshot into that index only, then diff the base against it with --binary --full-index. Never modify the real index, worktree, branches or commits for reporting. Capture separate base-to-HEAD, HEAD-to-index and index-to-worktree patches when relevant. Validate against status, name-status and untracked inventory; if a change is missing, investigate and add a safe separate patch or sanitized attachment, documenting the reason. Binary patches are not human-readable; add safe contextual evidence where necessary.

## Security and publication
Exclude secrets, real .env files, credentials, sensitive data, caches, build outputs and downloaded dependencies. Do not force-add ignored files. Inspect candidate changes and history before export, including tracked files and deleted lines. If sensitive content or uncertain paths exist, do not run the default exporter until safe; use a narrowly scoped sanitized export and record exclusions and coverage gaps. Never upload raw secrets even if already tracked. Inspect untracked and ignored relevant paths; use sanitized examples or documentation for relevant ignored files. Report every relevant omission. Do not zip until human-readable report, manifest and evidence have been checked for sensitive content, completeness and size. The script is a capture helper, not a secret scanner or proof of coverage. Keep output local until developer chooses to share.
